8. B11 EXACT TRANSFORMATION EQUATIONS
============================================================

[Reachability Owners]
- Provider subdomains: NATIVE_ACTIVE_PATH_B and WEBCAMTEXTURE_FALLBACK.
- Current accepted source set excludes configured-empty StaticImage and Video arrays.
- User horizontal flip false/true is reachable through the release ImageSourceConfig.
- Native fixed metadata: f=0, m=0, r=0.
- Fallback contract fields: f=WebCamDevice.isFrontFacing, m=videoVerticallyMirrored,
  r=videoRotationAngle. Their actual per-device values/correlations are Runtime-
  unverified; the matrix below covers the full current statically admitted enum/
  boolean contract without claiming those rows were observed.

[Definitions in normalized top-left S]
- P=(x,y).
- f=isFrontFacing; u=isHorizontallyFlipped; m=isVerticallyFlipped, equal to fallback
  videoVerticallyMirrored; expectedToBeMirrored=false at the current call site.
- a=f XOR u.
- j=1 for r in {90,270}, else 0.
- Installed ImageTransformationOptions.Build gives:
    h = (!j) AND a
    v = if !a then !m else if j then m else !m
- H(x,y)=(1-x,y); V(x,y)=(x,1-y).
- F_hv=V^v o H^h. H and V commute with each other only; no flip is commuted with r.
- D is Runner's optional aspect-preserving MediaPipe downscale. In normalized
  coordinates D(P)=P.

[MediaPipe]
- TextureFrame.ReadTextureInternal uses Graphics.Blit scale=(-1 when h, -1 when v)
  and offset=(1 when flipped), so a source feature P appears in the task-input image
  at F_hv(P).
- The task then preprocesses with R_r. Its model-input point is locally
  R_r(F_hv(P)) after ROI/crop/resize/letterbox.
- The v0.10.22 top-level/final projection contract returns coordinates in the
  unrotated, uncropped task-input image. It cancels R_r without assuming
  R_r o F_hv = F_hv o R_r.
- Therefore M(P)=F_hv(P).

[IE]
- Let B(x,y)=(x,1-y) convert top-left S to Unity bottom-left UV and let C be the
  same-sample bottom-left cropMatrix mapping crop UV q to unflipped source UV.
- Shader sampling order is exact column-vector order:
    sourceUv = F_hv,BL * C * q_BL
  because ScheduleModel uses BuildFlipMatrix(h,v) * cropMatrix.
- For source feature P, the corresponding ideal crop-local point satisfies:
    F_hv,BL * C * q_BL = B(P)
- Decoder uses raw top-left model y -> q_BL, then reports B(C*q_BL). Since each
  reflection is self-inverse and B conjugates it to the same normalized top-left
  reflection:
    I(P) = B * C * C^-1 * F_hv,BL^-1 * B(P)
         = B * F_hv,BL * B(P)
         = F_hv(P)
- Thus M_x(P)=I_x(P) and M_y(P)=I_y(P) for arbitrary P and every admitted state.
- Z is also convention-compatible: reflection F is orthogonal, so
  |F_hv,BL*C*e_x|=|C*e_x|. Neither flip signs nor rotation preprocessing changes the
  projected ROI X-axis magnitude convention.
- ROI roll, provider-specific recurrence, and numerical predictions are not assumed
  equal and are outside B11 coordinate-semantic equality.
- Screen/RawImage preview transforms are downstream presentation only and are not
  included in M or I.
