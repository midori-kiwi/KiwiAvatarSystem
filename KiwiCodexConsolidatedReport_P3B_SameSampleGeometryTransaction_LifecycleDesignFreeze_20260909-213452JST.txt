5. EXECUTION LANE / GRAPH QUEUE / FLOW LIMITER
======================================================================

[External Primary Admission Owner]
- Geometry lifecycle owner state is exactly IDLE or IN_FLIGHT, plus at most one
  LATEST_PENDING transaction.
- In IDLE, admit the newest transaction and transition to IN_FLIGHT only after
  successful packet ownership transfer.
- In IN_FLIGHT, atomically replace LATEST_PENDING. Dispose the replaced immutable
  first468 payload immediately. Do not add it to the graph.
- Callback completion moves one bounded result into COMPLETION_READY. Main-thread
  drain validates and retires the exact in-flight token, then may admit the latest
  pending transaction if still current.
- No Queue<T>, List backlog, FIFO history, permanent delay, or multi-frame graph
  admission is permitted.

[Graph Queue Safety]
- CalculatorGraphConfig exposes max_queue_size and report_deadlock.
- Official generated comments state default max_queue_size is 100; -1 disables
  throttling; when report_deadlock is false, an input queue may be enlarged to
  resolve a scheduler deadlock.
- Use max_queue_size=1 as a secondary fail-closed safety limit and
  report_deadlock=true. This prevents automatic queue expansion from becoming
  normal behavior.
- The graph has one externally admitted FACE_LANDMARKS stream. No second packet is
  added while IN_FLIGHT, so AddPacketToInputStream is never used as a wait/queue
  mechanism. A queue/deadlock error is a graph fault and triggers bounded reset;
  it does not authorize expansion or blocking retries.

[FlowLimiter Comparator]
- Installed FlowLimiterCalculator is registered, but it adds FINISHED feedback,
  another admission/queue owner, and retained queue state.
- The explicit external one-in-flight/latest-pending owner is smaller and preserves
  Kiwi latest-frame policy. FlowLimiter is not needed and must not be layered on.

6. OUTPUT ACQUISITION / POSE-ONLY STOP BOUNDARY
======================================================================

[Callback Selection]
- OutputStreamPoller.Next is blocking and is not selected. No main-thread poller
  and no extra worker thread are required.
- CalculatorGraph.ObserveOutputStream exposes NativePacketCallback(graphPtr,
  streamId, packetPtr). Its generic wrapper creates Packet<T>.CreateForReference;
  that wrapper is non-owning.
- Installed OutputStream demonstrates the IL2CPP/AOT pattern: a static callback
  annotated MonoPInvokeCallback and an instance table keyed by stream id.
- P3C design must use one static rooted delegate and a registry entry that also
  verifies graph identity/lifecycle generation. Register before StartRun; mark the
  registry non-accepting before graph shutdown; remove it only after callbacks
  have quiesced.
- Callback does no Unity API work, no main-thread state access, no blocking wait,
  and no unbounded allocation/work.
- packetPtr is borrowed/native-owned and may not survive callback return. The
  callback must extract/copy the required immutable result before returning and
  never retain Packet<T>, packetPtr, FaceGeometry, or native mesh storage.
- Callback exceptions are converted to a graph error/status; the in-flight token
  is retired and graph fault recovery is bounded.

[Installed Pose Extraction Audit]
- FaceGeometry proto has field 1 Mesh and field 2 PoseTransformMatrix.
- PacketGetterExtension.Get<T> calls mp_Packet__GetProtoMessageLite, receives a
  SerializedProto for the full message, and deserializes it with the supplied
  parser.
- The specific mp_Packet__GetFaceGeometry export also returns SerializedProto for
  the full FaceGeometry.
- FaceLandmarker.GetFaceGeometryList calls packet.WriteTo(FaceGeometry.Parser),
  deserializes full FaceGeometry objects, then reads PoseTransformMatrix.
- The exact installed DLL contains FaceGeometryPipelineCalculator and MatrixData,
  but no registered FaceGeometry-field-to-MatrixData extraction calculator was
  found. Searches for FaceGeometry-to-matrix/proto-field calculator names in
  installed source/config and calculator registration strings found none.
- A managed parser that skips Mesh would still receive/copy the complete serialized
  proto bytes across the native/managed boundary. It does not satisfy the explicit
  no-mesh-cross-boundary requirement.
- Unsafe inspection of a native C++ packet object is not a supported ABI and is
  rejected.

[Exact Unresolved Boundary]
- Desired payload is correlation timestamp + raw 16-float MatrixData + status.
- Achieving it requires a native registered calculator that maps FaceGeometry to
  MatrixData (the existing generic MatrixData getter can then copy only the small
  proto), or a new purpose-built native getter. Either changes the installed
  package/native artifact/provenance scope and is forbidden in P3B.
- No diagnostic micro-probe can turn this static API/registration absence into the
  required pose-only path, so none was run.
