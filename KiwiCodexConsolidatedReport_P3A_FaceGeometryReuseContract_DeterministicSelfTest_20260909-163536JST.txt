[Current Static IMAGE_SIZE Dataflow]
- AppSettings.asset selects the Windows preferred source profile 1920x1080@60.
- WindowsNativeWebCamSource uses that preferred width/height for its fixed native
  texture wrappers and stable presentation texture.
- Face Landmark Detection.unity serializes downscaleTrackingInput=1 and
  trackingInputMaxWidth=480.
- FaceLandmarkerRunner starts from the source Texture dimensions and computes an
  aspect-preserving tracking copy. For 1920x1080:
    scale=480/1920=0.25
    rounded height=RoundToInt(1080*0.25)=270
    even adjustment keeps 270
- Runner then reads that 480x270 tracking Texture into the Image supplied to the
  Face Landmarker Task. Official FaceLandmarkerGraph obtains IMAGE_SIZE from
  ImagePropertiesCalculator on that Task IMAGE.
- IE samples the 1920x1080 source Texture but publishes normalized T coordinates.
  192x192 is only the IE crop/model plane and is not FaceGeometry IMAGE_SIZE.
- 480/270=1920/1080=16/9 exactly. No resize rounding changes the aspect ratio.
- Therefore exact Task-oracle baseline IMAGE_SIZE is 480x270. The normalized IE
  result on 1920x1080 is aspect-equivalent. Diagnostic execution independently
  returned byte-identical output at both absolute sizes.
- Runtime fallback/source dimension changes are not claimed absent. A later carrier
  must bind the same-sample semantic image aspect; this task ran no camera.

[Static Source Contract]
- FaceGeometryFromLandmarksGraph receives vector<NormalizedLandmarkList> plus
  pair<int,int> IMAGE_SIZE and optional Environment; it splits every list to the
  first 468 landmarks before FaceGeometryPipelineCalculator.
- Default Environment is TOP_LEFT_CORNER, VFOV=63 degrees, near=1, far=10000.
- GeometryPipeline requires the landmark frame and IMAGE_SIZE to have the same
  aspect ratio; absolute size affects the frustum only through aspect.
- ProjectXY owns TOP_LEFT -> internal Y orientation conversion. ChangeHandedness
  owns the screen-left-handed -> metric-right-handed Z sign conversion.
- The pipeline uses relative weak-perspective input Z, two scale estimates,
  unprojection, final weighted orthogonal Procrustes pose estimation, and then
  multiplies runtime metric landmarks by inverse pose before output mesh packing.
- Procrustes disallows reflection and produces a uniform-scale rotation plus
  translation with matrix last row [0 0 0 1].
- FaceGeometry proto guarantees mesh XYZ in right-handed Metric 3D and guarantees
  screen XY only after mesh -> pose matrix -> same-environment perspective project.
- Canonical metadata declares centimeter units.
- No master/latest or legacy mediapipe/modules/face_geometry source was used as
  Primary.

6. OUTPUT SEMANTIC FREEZE
============================================================

[Static + Executed Contract]
- INTERNAL_RUNTIME_METRIC_LANDMARKS are the right-handed points after final
  unprojection and handedness crossing, before inverse pose normalization.
- POSE_TRANSFORM_MATRIX maps canonical/output-mesh coordinates to runtime metric
  face coordinates. It contains uniform scale, rotation, and translation.
- OUTPUT_FACE_GEOMETRY_MESH copies canonical UV/topology and replaces XYZ with
  inverse-pose-transformed metric landmarks. It is pose-normalized/canonical-
  aligned residual geometry.
- Correct validation is:
  output mesh XYZ -> raw pose_transform_matrix -> perspective projection under the
  same Environment/aspect -> TOP_LEFT normalized screen XY.
- P3 does not transpose/invert/convert the pose to a Unity Transform and does not
  use the plugin's Unity-facing Matrix4x4 conversion, which changes handedness.
- Origin conversion owner=official GeometryPipeline ProjectXY/projection inverse.
- Handedness conversion owner=official GeometryPipeline ChangeHandedness.
