3. REQUIRED SOURCE IDENTITY CONTRACT AUDIT A-J
===============================================================================

A. Runner source-frame owner

FaceLandmarkerRunner.StoreSentisTrackingData assigns:

  precisionData.frameId = ++_nextPublishedTrackingFrameId;
  acceptedFrameId = precisionData.frameId;

This occurs under the existing tracking locks after the result passes validity,
geometry, and monotonic semantic timestamp handling. MediaPipe publication uses
the same counter for its own published samples, so it remains one Runner source
publication identity domain.

B. P3D acceptedFrameId identity

The exact acceptedFrameId returned from StoreSentisTrackingData is passed to
AdmitFaceGeometryTransaction and then unchanged to
KiwiFaceGeometryTransactionService.AdmitAcceptedInferenceResult. InputTransaction
stores that frameId; the graph packet timestamp is the same frameId; a valid
completion publishes it in one immutable AcceptedSnapshot.

C. Same provider sample entering ProviderHub

KiwiTrackingProviderHub.ObserveBuiltInRunner reads the Runner's immutable latest
FacePrecisionTrackingData. New source samples are admitted only when data.frameId
is valid/nonzero and differs from _lastObservedRunnerFrameId. Backend selects the
dedicated Inference or MediaPipe slot.

D. providerSourceFrameId assignment

The built-in path calls UpdateSlot with both sourceFrameId and
providerSourceFrameId equal to data.frameId. NormalizeProviderFrame constructs
KiwiTrackingNormalizedFrameMetadata with:

  providerSourceFrameId: providerSourceFrameId

E. Exact preservation

For built-in Runner providers, normalization.providerSourceFrameId is the exact
Runner data.frameId. It is not _hubFrameId, Unity display frame,
canonicalFrameId, normalized external sequence, or another synthesized counter.
External providers may have a separate normalized arbitration identity, but an
absent exact providerSourceFrameId stays zero. The repaired P3D bridge fails
closed on metadata invalid or providerSourceFrameId zero.

F. Atomic same-sample association

ProviderSlot receives data, immutable normalization metadata, sourceFrameId,
arrival ticks, and slot identity in the same main-thread UpdateSlot operation.
PublishIfChanged copies selected.slot.data and selected.slot.metadata from that
same selected slot. KiwiCanonicalTrackingFrame.Publish then constructs one
readonly KiwiTrackingFrame containing providerId, rigid, normalization, and the
current generation snapshot under its Sync lock. sourceHostTicks, provider
identity, generation, normalization, and providerSourceFrameId are therefore
paired at the Canonical latch.

G. Switch / Resume / restart / replacement

- a real provider switch advances ProviderGeneration before Canonical capture;
- same-provider Resume does not fabricate a provider switch or source identity;
- a new source frame replaces the same slot's data+metadata together;
- scene load advances TrackingSessionGeneration, clears both built-in slots,
  metadata, source identities, published state, switch state, and handoff state;
- Canonical reset/disable clears its current frame;
- P3D shutdown/graph reset clears AcceptedSnapshot;
- the final exact source identity, generation, backend, timestamp, dimensions,
  and revalidation gates reject stale slot or old-run mixing.

H. rigid.frameId authority

PublishIfChanged intentionally increments _hubFrameId and assigns it to
output.frameId. This remains the hub-local publication identity used by canonical
publication/latching. The repair does not change _hubFrameId or rigid.frameId.
