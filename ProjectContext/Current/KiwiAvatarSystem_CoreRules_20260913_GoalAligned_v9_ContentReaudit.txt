# 0. 主目的

Windows / DX12を第一対象としてFace LandmarkerをPrimary / Source of Truthに維持し、正常な最新face sampleを最小latency、高精度、低jitterでKiwi Avatarへ反映する。

Root / Head / Eye / Blink / Mouth / Expression / FacePartを自然かつ正しく表示し、LIVE CAMERA、Spout / OBS、Avatar Import、Recovery、Diagnostics、Distributionまで含む実用的な商用品質のAvatar製品としてWindows Production Acceptanceを完成させる。

写実的な別人化は製品目的ではない。正常sampleのPrimary pathは可能な限り短く保ち、
`Face Landmarker → Canonical Semantic / Transaction → Model Profile → Face-Part Binding → Kiwi Presentation`
を基本とする。Neural portrait / face replacementはPrimary pipelineへ昇格させない。

検証、診断、Phase、FaceGeometry、H1、backend、architectureは手段であり目的ではない。各作業は最終ユーザー可視要件、または不可欠なCorrectness / Authority / Transaction / Lifecycle / Resource / Security / Privacy / Performance / Compatibility / Release契約へ直接寄与する場合だけCritical Pathへ置く。

閉じたclaimは新Evidenceなしに再実行しない。同じ保証を少ないowner、state、copy、queue、Gateで得られるなら簡素化する。最終品質を下げる簡略化は禁止する。

# 1. 品質契約

必須品質:
- 低遅延
- 高精度
- 低ジッター
- 高速追従
- 静止安定
- 正しいYaw / Pitch / Roll
- 正しいRoot
- 自然なEye / Blink / Mouth / Expression
- 正しいFacePart
- 安全な短時間dropout
- 安全なLost / Reacquire
- 安全なProvider / Backend / Model transition
- 非球形Avatar対応
- Runtime Avatar Import
- Transactional Hot Swap
- Recovery / Diagnostics / Distribution

正常時latencyを犠牲にして問題を隠す設計は採用しない。

Quality Profile / tierはPresentationや計算量の合法な選択肢として設けてもよいが、Authority、identity、semantic correctnessを変えたり、不具合を隠したりしてはならない。

ユーザー可視方向契約:
- tracked screen-right translation → Avatar screen-right
- tracked screen-left translation → Avatar screen-left
- face right / left → Head yawを意図した同方向へ
- lean right / left → Head rollを意図した同方向へ
- down-right等の複合orientation → Head orientationへ
- Yaw / Pitch / RollをRoot translationへ混入しない
- Eye / Blink / Mouth / ExpressionをRoot translationへ混入しない
- frontal stillnessは不要な揺れを抑え、通常運動はNear-Raw responsivenessを維持する

# 2. Claim-Scoped Authority

Authorityはclaim単位で使う。

- Implementation: current live-local Production source + actual SHA
- Runtime: same-build / same-Production
- Package: actually installed Package Source
- Performance: clean Production benchmark
- Visual: same-build Human review
- Provenance: source → build definition/toolchain/flags → artifact → installed SHA → Runtime Evidence

通常チャットがlive localを直接確認できない場合:
`NORMAL_CHAT_LIVE_LOCAL_PRODUCTION_NOT_DIRECTLY_VERIFIED`

Codex REPORTのbranch / HEAD / SHAはreport-time snapshotでありcurrent liveへ自動昇格しない。

GitHub remote/mainやGitHub commitはlocal Production Runtime Authorityではない。

EXE / DLL SHA単独でreproducible-build Authorityへ昇格しない。

SHA推測禁止。未確認は合格でも不合格でもない。

Observer、Validator、Benchmark、REPORT、capture surface、measurement designも監査対象。

新Evidenceで旧Current / Next / SHAがSupersedeされた場合は再昇格しない。

# 3. Project-wide Double Full Audit

KiwiAvatarSystemに関する技術的意味を持つすべての調査、設計、指示、実装、検証、評価、判断、技術成果物は原則FULL_AUDIT_1 + FULL_AUDIT_2の対象とする。

各回は同一対象・同一scopeを最初から最後まで100%独立監査する。

禁止:
- scope分割による2-pass
- 1回目=Source、2回目=Runtimeのような不完全分担
- 2回目=変更箇所だけ
- 1回目の結論をAuthorityにした追認
- 不一致の多数決PASS

不一致時はAuthority、identity、assumption、observer / validator、measurement design、claim scopeまで戻る。解消できなければUNRESOLVEDとして affected Gateを停止する。

書込み、build、Runtime capture、installer、commit、push等の副作用操作を監査回数だけを理由に二重実行しない。再現性・determinism・flakinessがclaimの場合のみ必要回数実測する。

過去チャット / ドキュメント / ChatReportを再監査する場合、タイトル、ファイル名、Archive一覧、旧summaryだけで技術結論を出さない。利用可能なら本文を開き、Objective / Evidence / Validated / Rejected / Superseded / Current Result / Open Issues / Next / Do Not Changeまで確認する。本文取得不能な資料は未確認として扱う。

# 4. 開発原則

Working Coreを理由なく再設計しない。

変更前にcurrent local source / Runtime、実使用Package Source、official Source / docs、類似OSS、公開商用方式をclaim単位で比較する。

評価対象:
- correctness
- latency
- authority
- transaction
- lifecycle
- resource
- security / privacy
- rollback
- compatibility

最初に証明されたboundaryだけを最小修正し、複数unknownを同時に修正しない。

前提、identity、proxy、observer、validator、benchmarkが欠陥なら測定設計まで戻る。

新owner / state / copy / queue / readback / thread / process hopは利益がcost / riskを上回るEvidenceなしに恒久追加しない。

Big-Bang rewrite、external tracker Primary置換、Neural Primary化は棄却。

# 5. Tracking / Transaction

Face Landmarker = Primary / Source of Truth。

正常sampleを最小latencyでAvatarへ届け、異常sample、authority transition、broken transaction、presentation破綻だけ局所抑制する。

維持:
- latest-frame
- persistent ROI / persistent tracking where required
- bounded / nonblocking
- freshness / liveness / source age分離
- tracking cadence / presentation cadence分離
- explicit dropout / Lost / Reacquire state
- channel-specific temporal policy
- same-sample transaction

禁止:
- latency-growing FIFO
- stale queue / accumulation
- permanent frame buffer / permanent 1-frame delay
- stale prediction
- strong smoothing / Kalmanで根本問題を隠す
- 根拠なきthreshold緩和
- aggressive frame reduction first

短いdropoutを即Lostへ変換しない。Lost / Reacquireはage、liveness、quality契約で扱う。

Root / Head / Eye / Mouthを分離し、Headはsingle rigid authority。

Yaw / Pitch / Roll、Blink、Mouth、EyeをRoot translationへ混入しない。

Provider normalization owner=1。
Resume != Provider Switch。
Temporal Presentation owner=1/channel。
Prediction owner=1/channel。

duplicate / out-of-order / stale / mixed epoch publish禁止。

Texture / Crop / Mask / FacePart=same-sample transaction。

Camera / Inference / Presentation問題をtracking mathへ逆流させない。

# 6. Human-Head / FacePart

Kiwiは変形しない剛体の人間頭部として扱う。

Eye / Mouthのnon-rigid appearanceを残し、
source rigid poseのみ除去
→ head-local / canonical appearance
→ existing fitted fixed surface
→ visible Head rigid poseをexactly once適用する。

source appearance de-rigidization referenceとvisible Head authorityは別責務。

FaceGeometry poseがあることだけを理由にvisible Head authorityへ昇格しない。

billboard、2D facial inverse UV、model deform補償をProduction解にしない。

# 7. Native / Inference

Windows / DX12優先。

Native baselineは新Evidenceで置換されるまでPath B SystemMemoryNV12。

維持:
- latest frame
- fixed Unity-visible texture identity
- explicit timestamp
- session / generation epoch
- session epoch != frame sequence
- bounded resource
- nonblocking normal path

禁止:
- UpdateExternalTexture workaround
- callback / workerを跨ぐIMFSample保持
- FIFO / stale蓄積
- blocking D3D12 queue Wait
- rotating Unity-visible texture
- D3D11On12 1080p Production

Fence / queue flush / async disableはcausal proofなしにProductionへ入れない。

Native変更はsource → build definition/toolchain/flags → artifact → installed SHA → Runtimeで追う。実build definition不明のまま推測Rebuildしない。

Inferenceではlogical tensor sizeとbacking capacityを混同しない。worker-owned output lifetime、async queue / readback lifetimeをCorrectness対象とする。

Production lane.input direct readback / copyを新Evidenceなしにoracleへ戻さない。

速度だけでbackend採用しない。backend epochを跨ぐold/new in-flight publicationを分離する。

KiwiFaceMotion / KiwiInferenceFaceTrackerをcamera/display workaroundにしない。

# 8. Validation / Regression / Performance / Visual

Static / installed Package Sourceで閉じるclaimをRuntime化しない。

検証は原則:
Change-Local Gate
→ Contract / Replay Gate
→ Milestone Full Product Gate

同claimの多重observer、superseded diagnostic、毎version Full Runtime / Human Visualを削減する。

Golden Replay:
- bad behaviorをGolden化しない
- auto-update禁止
- Runtime transitionはRuntime PASS後にGolden昇格

owner/pathをretireしたら専用diagnostic / validatorもretire候補。

Correctness observer-heavy runをPerformance Authorityにしない。

最終Performance比較では可能な限り事前にSLOをfreezeし、correctness-qualified候補だけ比較する。

Human Visualをvalidator / log PASSで上書きしない。

H1の継続的position / rotation jitterを相関するHuman Visual measurementでは、瞬間Space markerを使用しない。同一artifactの連続録画をHuman Visual Authorityとし、diagnosticが固定segment `NEUTRAL_STILLNESS_A` / `SLOW_YAW` / `SLOW_PITCH` / `SLOW_ROLL` / `NEUTRAL_STILLNESS_B` の開始/終了をtimestamp化する。最優先は入力顔が実質静止した `NEUTRAL_STILLNESS_A` 全期間。reject / identity failureは録画上の不安定windowと継続相関しない限り原因へ昇格しない。相関不能はUNRESOLVEDとしてmeasurement designへ戻る。MATCHED LANDMARK DEBUGのWAIT/復帰はHuman Product failureとして扱わない。

ユーザー向け確認項目と判定は日本語を主表記にする。判定は「合格 / 不合格 / 未確認 / 対象外」を基本とする。英語内部キーは既存log/reportとの照合時だけ日本語の後へ併記する。

# 9. Avatar Product / Config / Security / Privacy / UX

Target:
Evidence-Protected Core
+ Avatar Adapter
+ Model Profile
+ Runtime Import
+ Transactional Hot Swap

VRM 0.x / 1.0、non-spherical、generic FacePart、AutoFit、Spring / Dangle等のmodel-specific behaviorをTracking Coreへ逆流させない。

AutoFit authority:
- Head / Neck / Eye bones
- model forward
- head bounds
- model scale
- profile hints

AutoFitはFaceAnchor / Eye / Mouth / FacePart placementをmodel固有層で解く。
自動配置が成立しない場合はmanual Model Profile overrideへ落とし、Tracking Coreを補償変更しない。

Transactional Hot Swapはhidden candidateで:
load
→ parse
→ security / format validation
→ model / humanoid validation
→ Model Profile
→ AutoFit
→ expression / Spring setup
→ Avatar Adapter bind
→ transaction validation
→ atomic active switch
→ old dispose
の順を基本とする。途中失敗時はactive modelを維持してrollbackする。model / profile epochを跨ぐmixed publicationは禁止。

Runtime Importと同じboundaryで:
- extension + magic検証
- path traversal防止
- parse isolation
- resource / memory limits
- cancellation
- generated storage naming
- external path restriction where applicable
- atomic failure
- rollback

Config:
- explicit priority hierarchy
- atomic save
- versioned migration
- backup
- last-known-good
- safe fallback
- user tuning boundary

Calibration / User Tuning:
- neutral face / head / eye / expression
- face center / model placement
- Head / Root / Eye gain
- Blink / Mouth sensitivity
- rest stability / dropout behavior
- model-specific FacePart offset / scale where appropriate

User tuningとinternal correctness stabilizationを分離し、設定で不具合を隠さない。

Quality Profileで変更できるのはrendering quality、render FPS、preview、validated inference cadence、optional workload等の合法な範囲に限定する。
semantic acceptance、tracking correctness、transaction gate、Authority、identityをProfileで変更しない。

Product UX:
- Model Browser
- Camera / Provider状態
- Calibration / Profile / Tuning
- Quality setting
- Health / Diagnostics
- clear error / recovery
- support bundle where justified
- privacy / security UX
- high-DPI / resize / multi-monitor robustness where applicable
- keyboard operation / Accessibility for core UI where applicable
- nonblocking progress
- cancelable import

DiagnosticsはProduct authority ownerにならない。

Windows Product completionではregistered SLOとrepresentative Support Matrixを閉じる。UX / Accessibilityも完成品質に含める。

# 13. Commit / Push

意味のある最小変更がStatic reviewを通り、次のlocal検証用の再現可能な基準点を固定すべき時点がcommit boundary。

通常チャットはその時点で必ず「今がコミット適切時点」と知らせる。

2026-09-13にユーザーからKiwiAvatarSystemの今後の通常commitと通常pushへstanding permissionが与えられた。撤回されるまで、適切なcommit boundaryでは個別確認なしでcommitし、そのcommitを通常pushしてよい。

WIPを細切れにcommitしすぎず、複数の独立boundaryを1 commitへまとめない。

standing permissionはforce push、destructive history rewrite、tag/release、reset/clean、user-owned dirtyを破棄するcheckout/restoreを許可しない。これらは別途明示許可を必要とする。

local Production検証前のcommit/pushはProduction採用を意味しない。

コード変更前Preflight:
- ProjectVersion.txt
- exact Unity.exe path/version
- branch / HEAD / status
- user-owned dirty保護
- touched file before SHA
- candidate SHA
- after SHA

reset / checkout / clean禁止。

Windows PowerShell 5.1固定。

safe I/O、subprocess exit code、transactional replacement、rollback、write-target guardを使用。
