# KiwiAvatarSystem 情報源構成・Current Selector運用

更新日: 2026-09-14 JST
Revision: v4 / Current Integrated / Artifact Governance / GitHub Preauthorized

## 1. 目的

Current情報源を分散させず、古いNext / SHA / phaseを再昇格させない。
同時に、完全ロードマップから現在地を切り離さない。

今回から `CurrentRoadmap` 単独文書を廃止し、Currentを完全ロードマップへ統合する。

技術作業はCoreRulesに従い、必要な因果経路を1行・1式まで監査し、修正前にofficial docs/source・Package・関連公開実装・実践/検証動画・既存Evidenceを比較する。フレーム系列claimは対象windowの全フレーム解析を原則とする。GitHubの通常commit/pushは必要範囲で事前許可済み。

## 2. Current selector

`D:\KiwiAvatarSystem\ProjectContext\Current\`

Currentとして置くのは原則3ファイルだけ。

1. `KiwiAvatarSystem_CoreRules_*.txt`
2. `KiwiAvatarSystem_FullRoadmap_*.txt`
3. `KiwiAvatarSystem_CustomInstructions_*.txt`

Directory membershipをCurrent selectorとする。
ファイル名のlatest/final/revision/mtimeだけでCurrentを決めない。

旧 `KiwiAvatarSystem_CurrentRoadmap_*` はCurrentから外し、Historicalへ移す。
削除して履歴を消す必要はないがCurrent selectorへ残さない。

## 3. FullRoadmapの役割

FullRoadmapが次を一元管理する。

- report-time Current identity
- Current Authority / Environment
- Current Product Problem
- Validated / Retained Decision Ledger
- Rejected / Superseded / Do Not Re-promote
- Current First Blocker
- Open Issues
- Next Single Action
- プロジェクト開始から現在までの目的 / 内容 / 結果 / 現在の扱い
- 現在からWindows Production完成までの全Critical Path
- Windows Definition of Done
- Optional / Deferred lane
- Mobile preparation

Currentと完全ロードマップを別文書へ分離しない。

## 4. CoreRules

恒久契約だけを持つ。

- Primary Goal
- Claim-Scoped Authority
- Double Full Audit
- Tracking / Transaction rails
- Native / Inference rails
- Human-Head / FacePart contract
- Validation philosophy
- Product quality / Security / Privacy / UX
- workflow / commit / safety

Current SHA、current phase、temporary hypothesis、Next Actionは入れない。

## 5. CustomInstructions

通常チャット用の圧縮コンテキスト。
CoreRulesとFullRoadmapを短く再現し、Current First Blocker / Nextを保持する。
詳細履歴はFullRoadmap / REPORTへ委譲する。

## 6. AGENTS.md

`D:\KiwiAvatarSystem\AGENTS.md`

Project root固定。Current selector外。
local agent durable policy、Preflight、Authority、安全、role split、audit contractを持つ。
volatile SHA / Runtime / Nextは入れない。

## 7. ProjectContext\Operations / Artifact Governance

`D:\KiwiAvatarSystem\ProjectContext\Operations\`

Current selector外の恒久運用文書を置く。

- `KiwiAvatarSystem_情報源構成_CurrentSelector運用_*.txt`
- `通常チャット運用管理規則_*.txt`
- `通常チャット用_恒久REPORT_ZIP直接作成指示_*.txt`
- `KiwiAvatarSystem_成果物フォルダ運用規則_*.txt`
- 対応するSHA256 manifest等

OperationsはCurrent技術状態を所有しない。volatile SHA、temporary hypothesis、Current Nextを独自に持たない。

技術成果物は`D:\KiwiAvatarSystem\ProjectArtifacts\`へ分離し、Artifact Owner単位でReports / Evidence / Logs / Visual / Packages等へ管理する。project rootへ通常REPORTやEvidenceを新規出力しない。保存場所はAuthorityではない。

既存root成果物は新規則適用のためだけに一括移動しない。参照元、script / validator依存、before path、SHA256を確認してtransactionalに移行する。詳細Authorityは`KiwiAvatarSystem_成果物フォルダ運用規則_*`。

## 8. ChatReport / Consolidated REPORT / KiwiValidation

Historical Evidence / detailed evidence。

- detailed chronology
- historical SHA
- Runtime/Visual/Performance evidence
- old diagnostic
- old Next
- observer/validator findings
- exact method/statement evidence

Current selectorへ大量投入しない。

過去を再監査するときはArchive名・タイトルだけで判断しない。
利用可能な場合はZIP内部の`00_CHAT_PERMANENT_REPORT.md`または対応REPORT本文を開き、
目的、Evidence、Validated、Rejected、Superseded、Current Result、Open Issues、Next、Do Not Changeを読む。
本文が取得できない場合は「本文未確認」とする。

技術再監査は必要な因果経路を1行・1式・statement / dataflow単位まで確認する。フレーム系列claimは対象windowの全フレーム解析を原則とし、代表frameだけで閉じない。

## 9. 旧Integrated Information

R12/R13等の旧巨大統合情報はHistorical Source。
現在も有効な原則はCoreRules / FullRoadmapへ移管し、旧Current / SHA / Nextは移管しない。

## 10. Current読み順

通常の再開:
1. AGENTS.md
2. CoreRules
3. FullRoadmapのCURRENT SNAPSHOT / Decision Ledger / Next
4. CustomInstructions
5. latest relevant Consolidated REPORT / Runtime / Human Visual
6. 必要なhistorical evidence

全履歴を毎回再展開しない。

## 11. Supersede手順

Current文書を更新する場合:
1. candidateを作る
2. FULL_AUDIT_1を同一scope全体で実施
3. FULL_AUDIT_2を独立に同一scope全体で実施
4. old CurrentをCurrent directoryから外す
5. historical storageへ保存
6. new 3-file Current setだけを残す
7. local branch/HEAD/statusを直接確認できた場合のみlive-localとして記録
8. GitHubの通常commit / pushは事前許可済み。branch / remote / diff / dirty保護を確認し、必要なboundaryで実行する

## 12. Current統合後の禁止

- CoreRulesとFullRoadmapの双方へvolatile Currentを二重所有させない
- FullRoadmapと別CurrentRoadmapを並行Currentにしない
- ChatReportのold NextをFullRoadmap Currentへ戻さない
- report-time HEADをcurrent liveへ昇格しない
- historical Runtime PASSをFinal Visual/Performance PASSへ拡張しない

## 14. 最終原則

Currentを小さくすること自体が目的ではない。
Current Authorityと完成ロードマップを一つに保ち、必要な過去経緯は同じFullRoadmapのchronologyへ残す。
詳細EvidenceはChatReport/REPORTへ委譲する。
