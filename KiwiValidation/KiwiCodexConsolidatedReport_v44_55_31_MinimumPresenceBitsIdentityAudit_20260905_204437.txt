14 Root Cause

Primary root cause:
  M3_VALIDATOR_STRING_COMPARISON_DEFECT

Exact causal chain:
1. Tracker captures float threshold into the transaction lane.
2. v25 converts the float to a signed C# int bit word.
3. v27 serializes that word as uppercase X8 CSV text.
4. v31 reads the same pair int and JsonUtility serializes it as a decimal JSON number.
5. PowerShell loads the JSON value as System.Int32 and CSV as System.String.
6. Old validator converts both to string and compares lexical text.
7. Decimal `1056964608` differs from hexadecimal `3F000000`, causing a false identity failure.

Secondary root cause:
  VALIDATOR_SELFTEST_FIXTURE_NOT_RUNTIME_FAITHFUL

The previous fixture copied a common numeric value through Export-Csv, so both synthetic sides had the same lexical form. It did not reproduce v27's uppercase X8 production serializer and could not expose the defect.

Root-cause class decisions:
- M1 signed/unsigned mismatch: REJECTED_FOR_THIS_RUNTIME; retained as defensive test dimension.
- M2 JSON parser/type defect: REJECTED; observed type is System.Int32 and is valid.
- M3 validator string comparison defect: CONFIRMED PRIMARY.
- M4 schema semantic mismatch: REJECTED; same bit semantics, different lexical encoding.
- M5 wrong-pair join: REJECTED.
- M6 capture timing/lifecycle divergence: REJECTED for minimumPresence identity.
- M7 hook defect: REJECTED for this failure.
- M8 real transaction identity defect: REJECTED for this failure.
