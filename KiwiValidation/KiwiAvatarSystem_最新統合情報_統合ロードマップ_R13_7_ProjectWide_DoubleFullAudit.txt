0B. PROJECT-WIDE UNIVERSAL DOUBLE FULL AUDIT POLICY

この規則は特定Phase、R13.5/R13.7、Codex指示、Runtime等に限定しない。
KiwiAvatarSystemプロジェクト全体へ横断適用するProject-level ruleとする。

主対象:

- 調査・比較
- 設計・Architecture・Design Freeze
- roadmap・作業計画・優先順位
- 通常ChatからCodexへの指示
- local Source / SHA / Provenance / Package監査
- 実装・修正・簡素化・retire
- Static / Semantic / Contract監査
- Validator / Observer / Diagnostic / Benchmark
- compile / build / ABI / artifact
- Runtime / Performance / Human Visual
- Authority / Transaction / Ownership / Lifecycle / Resource
- Replay / Regression / Security / Compatibility
- Reuse / Reject / Supersede / Rollback / Production採用
- Installer / Distribution / Release / Acceptance
- Codex REPORT / Runtime Evidence / integrated information / roadmap / handoff等の成果物
- 通常Chat自身の技術判断・次工程決定

各対象について:

FULL_AUDIT_1:
同一対象・同一scopeを最初から最後まで100%完全監査する。

FULL_AUDIT_2:
同一対象・同一scopeを再び最初から最後まで100%完全監査する。

FULL_AUDIT_2は
FULL_AUDIT_1の結論を前提・Authorityとして追認せず、
独立した再監査として扱う。

禁止:

PARTITIONED_TWO_PASS_AUDIT

すなわち、
1回目と2回目でscopeを分割し、
合計で1回分の全体監査にすることを禁止する。

不一致時:

FULL_AUDIT_1 != FULL_AUDIT_2

ならPASSへ丸めない。

Authority、identity、observer/validator、measurement design、
claim scopeまで戻って再確認し、
解消できなければUNRESOLVEDとしてGateを停止する。

副作用を持つ操作について:

2回の完全監査は、
同一の書込み・build・Runtime capture・installer適用・commit/push等を
機械的に2回実行することを意味しない。

副作用操作は必要回数だけ実行し、
その実行前の内容と実行後の結果を、
それぞれ2回完全監査する。

再現性・determinism・flakiness自体がclaimの場合のみ、
必要な複数回実測を別途行う。
