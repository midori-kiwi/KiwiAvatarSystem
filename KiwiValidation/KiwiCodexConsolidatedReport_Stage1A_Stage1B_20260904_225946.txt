6. STAGE 1A — SUBMISSION / QUEUE / COMPLETION MAP
======================================================================

[Static]

DIRECT_GRAPHICS:
  graphics Graphics.Blit crop write
  -> graphics temporary ToTensor CB submit
  -> graphics Worker internal model CB submit/clear
  -> post-submit static AsyncGPUReadback.Request(output buffer)

COMMAND_BUFFER_GRAPHICS:
  graphics Graphics.Blit crop write
  -> one graphics external CB: ToTensor + model
  -> post-submit static AsyncGPUReadback.Request(output buffer)

  graphics Graphics.Blit crop write
  -> one Default async-compute external CB: ToTensor + model
  -> post-submit static AsyncGPUReadback.Request(output buffer)

Exact CB_GRAPHICS ↔ CB_ASYNC critical-resource difference:
  1. async armのみSetExecutionFlags(AsyncCompute)。
  2. ExecuteCommandBufferAsync(...Default)対ExecuteCommandBuffer。
  3. resource instances、CB reuse、ToTensor statements、ScheduleWorker statements、
     output borrow、readback request、poll、clone、decodeは同じsource path。

[公開設計原則]

Unity 6 Graphics.ExecuteCommandBufferAsync:
  commandsは指定async compute queueで実行され、同一buffer内commandsは同じqueue。
  platform非対応時はgraphics queueへfallbackし得る。
  https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Graphics.ExecuteCommandBufferAsync.html

Unity 6 GraphicsFence:
  async/graphics queue同期に使用できる一方、GPU task write→別GPU task readのresource
  dependencyはUnityが自動処理するため通常explicit fenceは不要、と公開説明される。
  https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Rendering.GraphicsFence.html

Unity 6 AsyncGPUReadback:
  GPU dataをCPUへasyncに取得し、request objectがavailabilityを表す。
  request.doneはrequest処理完了を示す。
  https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Rendering.AsyncGPUReadback.Request.html
  https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Rendering.AsyncGPUReadbackRequest-done.html

[未確認]

Managed/package sourceと公開docsからは次を証明できない。
  actual D3D12 queue object / native command list
  Graphics.Blit crop writeからasync ToTensor readへのnative wait/barrier実体
  static AsyncGPUReadback.Requestが使用するnative queue/synchronization
  request.doneが直前のexternal async model producerをどのnative dependencyで包含するか

8. STAGE 1A — CANDIDATE BOUNDARY MATRIX A–F
======================================================================

A. Graphics crop write → async ToTensor texture read
  Evidence fit: HIGH。CBGとCBAの最初のqueue-crossing差。
  Discrimination: graphics→async input visibility/orderを直接問える。
  Risk: explicit fence/waitを入れると同期・latency・semanticsを同時に変える。
  Public constraint: Unityはresource dependencyを自動処理すると説明。
  Decision: PLAUSIBLE_UNVERIFIED。fence fixとして先行採用しない。

B. ToTensor execution / texture→tensor transition
  Evidence fit: MEDIUM_HIGH。CBAでinput conversionがasync CB上。
  Discrimination: ToTensorを分離するとqueue、submission count、input handoffが同時に変わりやすい。
  Risk: confounded diagnostic、追加cross-queue tensor dependency。
  Decision: PLAUSIBLE_UNVERIFIED、次手には非選定。

C. ScheduleWorker / backend external-CB submission form
  Evidence fit: LOW after v29。
  Discrimination: CBGが同じexternal CB formで88/88 REF_ONLY。
  Risk: package internal/external ownership変更は複数因子。
  Decision: REJECTED_AS_PRIMARY_FOR_THIS_SAME_BUILD_AB。

D. Worker-owned output lifetime / pool reuse
  Evidence fit: LOW for normal success path。
  Discrimination: distinct Worker/laneとreadbackPending guardがnext Scheduleを防ぐ。
  Risk: observer clone timingやpool behaviorを変える。
  Decision: NORMAL_NEXT_SCHEDULE_REUSE_REJECTED。
            exception/early-return pathのみSTATIC_GAP_UNVERIFIED。

E. Async model output → post-submit static readback boundary
  Evidence fit: HIGH。readback requestだけがexternal producer CB外で発行され、package/public
                managed contractはnative producer dependencyを閉じない。
  Initial proposal: same async CB内RequestAsyncReadback。
  Re-audit: Unity 6000.0のasync許可command一覧に含まれないため撤回。
  Replacement: D/Eのproducer-tail snapshotでstorage observation pathを比較する。
  Risk: compute copyとsecond readbackによるGPU/latency perturbation。
  Decision: PURE_SAME_ASYNC_CB_READBACK_PROPOSAL_REJECTED;
            D_E_PRODUCER_TAIL_SNAPSHOT_SELECTED。

F. CPU fallback flush / readback error / disposal edge
  Evidence fit: UNKNOWN。Package escape pathとhasError omissionは確認済み。
  Discrimination: model fallback set、error、lifecycle telemetryが必要。
  Risk:低いread-only inspectionは可能だが、async armだけのsemantic splitへ直結未証明。
  Decision: SECONDARY_UNVERIFIED。
