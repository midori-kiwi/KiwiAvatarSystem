Executive Summary
================================================================================

P2 RESULT: COMPLETE, subject to the explicit Unknowns and claim-scoped authority
limits in this report.

The current working Camera -> MediaPipe -> Canonical path is not supported for a
wide redesign. The shortest evidence-supported decision is NO_CHANGE for Native
Path B, camera latest-frame ownership, the Runner pre-input fresh/latest gate,
MediaPipe's internal flow limiter, callback-time result copying, claim-scoped
timestamps, and current Kiwi geometric rigid-head authority.

Four simplification findings are material:

1. FaceLandmarkerRunner contains 16 consecutive assignments of the same
   _observedFreshFrameSource expression and 16 consecutive calls to
   ObserveFreshFrameSource in the same loop region. PrepareFrameForUnity's Unity
   frame guard and the native sequence freshness guard make calls after the first
   normally idempotent, so this is not promoted to a Runtime defect. It is a
   statement-only MERGE candidate.

2. KiwiExpressionReaction directly consumes Runner expression state while
   FacePartShapeMask consumes canonical expression. This is a static owner bypass.
   A one-owner input architecture is preferable, but changing to the canonical
   accessor may alter freshness/coherence timing. Classification: MERGE candidate
   plus NEEDS_RUNTIME_EVIDENCE before adoption. Its presentation attack/release
   state remains a distinct channel responsibility and is not proposed for removal.

3. KiwiFacePartRigidSampleFrame and KiwiFacePartSharedTiltLock are both
   auto-installed and enabled by default. The first rotates SurfaceFittedRawImage
   uv0/uv1; the second independently computes the same rendered-eye-line correction
   and writes _SampleRotationRad. FacePartSoftMask then rotates the already-rotated
   mesh UV again. SharedTiltLock disables only the older FacePartAngleLock, not
   RigidSampleFrame. This establishes two current owners for the same sampling
   rotation claim. Retain RigidSampleFrame and classify SharedTiltLock as the
   strongest RETIRE_CANDIDATE, with a change-local Runtime/Visual gate before
   removal.

4. KiwiFacePartTextureTransaction does not carry native frame sequence. It matches
   a GPU history slot to Canonical submissionHostTicks by nearest time within 55 ms,
   constrained by camera/tracking generations. This is useful bounded correlation,
   but is not exact native-sample identity. F2 cannot be closed by renaming or
   merging tokens. No instrumentation is added in P2.

Sentis hybrid has concrete static responsibilities: a high-cadence 468-landmark
backend, persistent ROI lease, three bounded GPUCompute lanes, generation and
source freshness rejection before output readback, and MediaPipe-derived auxiliary
expression/rotation/anchor refresh at the serialized 10 Hz default. It also adds a
crop Blit, tensor conversion, output readback, model-specific state, and a second
landmark authority selected before Canonical. Source does not establish that its
quality/latency gain is necessary in current Product, nor that deletion is safe.
It remains KEEP_CURRENTLY / NEEDS_RUNTIME_EVIDENCE, not RETIRE_CANDIDATE.

The validation critical path can be reduced without weakening the completion gate.
v20/v24/v25/v27/v31, E2, and P1 PixelSpaceAudit should be frozen as historical
evidence or invoked only when their exact claim reopens. The recommended regression
shape is: change-local gate + Contract/Golden Replay gate + milestone Full Product
gate. Observer-heavy runs remain ineligible for Performance Authority.

Only two source-local simplifications have evidence stronger than NO_CHANGE:
(a) collapse exact duplicate Runner statements/calls without changing logic, and
(b) retire one of two active owners of the same FacePart sampling rotation, retaining

Native Camera Dataflow
================================================================================

The following is CLASS_B_STATIC unless a managed/DLL ABI statement is explicitly
identified. It preserves rather than replaces Path B.

1. StartInternal -> CreateMediaFoundationReader
   - MFStartup, device enumeration/selection, async IMFSourceReader creation.
   - MF_LOW_LATENCY is enabled; converters are disabled; exact NV12 media type is
     selected.
   - SourceReader callback object attaches the borrowed reader.
   - Three fixed CPU slots and three fixed GPU slots are lifecycle-owned globals.

2. SourceReaderCallback::RequestNext
   - Calls IMFSourceReader::ReadSample in asynchronous callback mode.
   - It does not wait for the sample.
   - One explicit request produces its corresponding OnReadSample completion.

3. SourceReaderCallback::OnReadSample
   - Executes on the SourceReader callback context, not Unity main thread.
   - Captures QueryPerformanceCounter arrival hostTicks.
   - Increments a local monotonically increasing native sequence.
   - llTimestamp is used for interval telemetry; it is not the downstream identity.
   - CopySampleToCpuLatest immediately copies the NV12 sample into a Kiwi-owned CPU
     slot using IMF2DBuffer2::Lock2DSize, IMF2DBuffer::Lock2D, or raw buffer Lock.
   - The callback does not retain IMFSample after return.
   - After the bounded CPU copy it calls RequestNext. Callback and shared state are
     synchronized; no Unity/render-thread wait is introduced.

4. CPU latest ownership
   - AcquireCpuWriteSlot finds a free slot or replaces the oldest Ready slot.
   - AcquireLatestCpuReadSlot selects the newest Ready slot and releases other Ready
     slots. This is latest-wins, not FIFO.
   - ProcessingWorker may block only on its condition variable while idle. That is
     a native worker-lifecycle wait, not a render/D3D12 queue wait.

5. ProcessingWorker -> ProcessNv12OnGpu
   - UpdateSubresource uploads Kiwi-owned NV12 bytes to a reusable D3D11 texture.
   - D3D11 copy/compute converts NV12 to RGBA and CopyResource moves the result into
     a D3D12-compatible shared resource.
   - Producer fence is signaled. There is no CPU/D3D12 blocking Wait.
   - ReclaimUnityCompletedSlotsLocked only polls completion.
   - If all three GPU slots are unavailable, work is dropped rather than queued.

6. RequestLatestPresent
   - Polls the producer completed fence and chooses newest completed Ready sequence
     greater than last requested sequence.
   - Returns slot index, sequence, hostTicks, and a borrowed ID3D12Resource pointer.
   - Marks PresentRequested; it does not transfer resource ownership.

7. OnRenderEvent
   - Called through the Unity plugin event for the selected slot.
   - Captures the Unity-side frame fence and moves the slot to AwaitUnity.
   - Later polling reclaims it nonblockingly after Unity completion.

8. StopUnlocked
   - Clears running, notifies and joins ProcessingWorker, Flushes SourceReader,
     detaches callback, releases resources, calls MFShutdown, clears slots and
     sequences. The join is allowed lifecycle blocking outside the normal frame
     path. A new Start is a new native session and sequence restarts from zero.

Official Microsoft comparison:
  IMFSourceReader::ReadSample asynchronous mode returns immediately, completion is
  delivered through IMFSourceReaderCallback::OnReadSample, timestamp is in 100-ns
  units, the callback must be thread-safe, and the application requests the next
  sample. The candidate source matches that control model.
  https://learn.microsoft.com/en-us/windows/win32/api/mfreadwrite/nf-mfreadwrite-imfsourcereader-readsample
  https://learn.microsoft.com/en-us/windows/win32/api/mfreadwrite/nf-mfreadwrite-imfsourcereadercallback-onreadsample

Decision:
  NATIVE_PATH_B_STATUS=KEEP
  CAMERA_LATEST_FRAME_STATUS=KEEP
  No FIFO, UpdateExternalTexture, sample retention, D3D11On12 replacement,
  blocking GPU wait, or rotating Unity-visible presentation identity is justified.

Unity Presentation Handoff
================================================================================

WindowsNativeWebCamSource.PrepareFrameForUnity:
  - once-per-Unity-frame guard;
  - TryRequestLatestPresent obtains newest completed borrowed native slot;
  - rejects sequence 0, duplicate/non-increasing sequence, invalid slot/resource;
  - creates at most one fixed Texture2D external wrapper per native slot;
  - does not call UpdateExternalTexture;
  - one Graphics.Blit performs Y normalization from the external wrapper to a
    stable linear ARGB32 RenderTexture named KiwiNativeCameraPresentation;
  - invokes the render event after queuing presentation work;
  - publishes presented native sequence and normalized hostTicks only after the
    handoff succeeds.

Identity and time owners:
  Native sequence: created by native capture callback; detects same-session order.
  Native hostTicks: QPC arrival in native callback.
  Managed hostTicks: calibrated once per camera session from native QPC frequency
  and anchor to managed Stopwatch frequency/domain; preserves ordering but is a
  converted correlation clock, not Media Foundation sample time.
  Camera generation: managed session/lifecycle owner; distinct from native sequence.
  Unity frame: presentation scheduling identity only.

Resource/lifecycle:
  The Unity-visible RenderTexture identity is stable within the camera session.
  Native slot wrappers persist per slot and are destroyed/recreated with source or
  session lifecycle. Pause/resume retains the session; Stop clears native/managed
  anchors, sequences, wrappers, and presentation state. Startup retries presentation
  for up to 300 Unity frames without adding a GPU blocking wait.

Classification:
  Fixed external wrappers=KEEP.
  Same-frame Y-normalizing presentation Blit=KEEP.
  Native sequence + managed camera generation=KEEP_AS_DISTINCT_CLAIMS.
  QPC-to-Stopwatch normalization=KEEP_FOR_CROSS_MANAGED_CORRELATION.

MediaPipeUnityPlugin 0.16.3 Audit
================================================================================

FaceLandmarker.CreateFromOptions:
  Builds a TaskInfo graph with IMAGE and NORM_RECT inputs, landmarks and output image,
  plus optional blendshape and face-geometry outputs. GenerateGraphConfig adds the
  flow limiter only for LIVE_STREAM.

FaceLandmarker.DetectAsync:
  ConfigureNormalizedRect is called with roiAllowed=false. Rotation is expressible;
  user ROI is rejected by this Task API. Timestamp milliseconds are converted to
  microseconds. Image and NormalizedRect packets receive the same timestamp and are
  moved into TaskRunner.SendLiveStreamData. The call is nonblocking with respect to
  graph completion.

TaskRunner/BaseVisionTaskApi:
  Input packet maps are move/dispose-owned by Send. Close closes graph input streams
  and waits for graph completion during lifecycle shutdown; it is not a per-frame
  wait. There is no Unity-main-thread callback marshal in the wrapper.

Callback ownership:
  The managed callback executes from the native graph callback context, outside the
  Unity main thread. FaceLandmarkerResult and nested List instances are preallocated
  and reused under an internal lock. The callback Image is wrapped in using and is
  disposed on callback return. Therefore Kiwi's copy-inside-callback and lifecycle
  gate are required; storing result/list/image references is unsafe.

Image ownership:
  Packet.CreateImage moves the managed Image wrapper into a native packet. In the
  CPU path, TextureFrame.BuildCPUImage wraps the Texture2D raw NativeArray with a
  void deleter, so raw pixel storage remains TextureFrame/Texture2D-owned. Kiwi's
  one-in-flight and deferred TextureFrame release are part of a real memory-lifetime
  contract, not redundant queue state.

TextureFrame CPUAsync cost:
  This is an asynchronous GPU->CPU transition, followed by Texture2D data load/apply.
  It avoids a synchronous ReadPixels/GetPixels production path, but it is not zero-
  copy. An optimization proposal needs installed-package-supported GPU input semantics
  plus clean Performance and lifecycle evidence. P2 proposes none.

Tutorial comparison:
  Plugin tutorial documents that DetectAsync returns immediately, callbacks execute
  outside Unity main thread, callback result references are shared/reused, and CPU
  pixel-copy examples are not an ideal high-performance production architecture.
  https://github.com/homuler/MediaPipeUnityPlugin/blob/master/docs/Tutorial-Task-API.md

Kiwi Runner owns:
  camera-source freshness before expensive conversion; one-slot latest mailbox;
  lifecycle/camera-generation acceptance; exact callback timestamp correlation;
  backend selection; copying reusable callback outputs; Canonical-ready snapshot.

Sentis hybrid owns when enabled:
  high-cadence alternative 468-landmark model execution; persistent pixel-square ROI
  lease; MediaPipe-to-future-Sentis ROI correction; stale source/anchor/generation
  rejection; alternate geometric rotation and expression fallback.

Overlap assessment:
  - Detection: no second Kiwi detector found in the audited main path.
  - Face tracking: MediaPipe previous-rect tracking and Sentis persistent ROI overlap
    in objective but belong to different model invocations. It is architecturally
    expensive, but not source-proven redundant while Sentis is primary.
  - ROI: Task API user ROI is unsupported; Kiwi's Sentis ROI is for its separate
    model crop, not a duplicate input ROI into FaceLandmarker.
  - Smoothing: MediaPipe landmarks smoothing is model-output stabilization;
    Kiwi Root/FacePart presentation state is channel-specific consumption. Mere
    plurality does not establish duplicate ownership.

Decision:
  Face Landmarker remains Primary / Source of Truth for detection and semantic
  calibration. Sentis must not be deleted from Static comparison alone.

    -> ProcessSentisFreshFrame
    -> KiwiInferenceFaceTracker.TryProcessAsync

Bounded resources/state:
  - three preallocated GPUCompute lanes;
  - persistent 192x192 crop resources and tensor/model worker;
  - each job records source hostTicks, ROI/crop, anchorRevision, externalAnchorEpoch,
    tracker generation, camera generation, tracking-session generation, and the
    submission-time minimum-presence policy;
  - stale generation, stale anchor, stale source, and cross-system stale results are
    rejected before ReadbackAndClone when possible;
  - newest valid source wins; no FIFO catch-up.

Concrete value:
  Supplies full landmarks at camera-fresh cadence while MediaPipe is deliberately
  refreshed at 10 Hz for auxiliary learned expression, matrix rotation, and ROI

  No clean same-build Product benchmark or paired visual/accuracy evidence in P2
  proves that hybrid output is better than standard FaceLandmarker-only output, or
  that FaceLandmarker-only meets Kiwi's cadence/quality contract. E2 is frozen and
  is not reopened.

Expression/Head Semantic Audit
================================================================================

Expression:
  MediaPipe v0.10.22 provides learned face blendshapes derived from smoothed
  landmarks. Runner copies them and, under Sentis-primary mode, caches them for up
  to 500 ms; after that, Sentis geometry heuristics provide fallback expression.
  Canonical latches expression only when its timestamp/backend coherence policy
  accepts it relative to rigid state.

  FacePartShapeMask consumes Canonical expression. KiwiExpressionReaction instead
  calls runner.TryGetLatestExpressionData directly and owns separate attack/release
  display state and loss behavior. The direct source is F1's static bypass.

  Decision: merge the input authority is a candidate; do not merge presentation
  response state. Runtime must show that canonical coherence does not create an
  unacceptable freshness/visual regression and that learned/fallback semantics are
  preserved.

Head:
  MediaPipe provides a facial transformation matrix. Runner copies its rotation and
  uses it as auxiliary information, but Kiwi's accepted rigid head is calculated
  geometrically from landmarks in the current backend path. The two outputs have
  different coordinate/calibration/model-dependence semantics. Existence of the
  matrix is not evidence that it is more accurate, lower-latency, or stable for this
  avatar coordinate system.

  Decision: retain Kiwi geometric rigid-head authority. MediaPipe matrix remains
  auxiliary/calibration input unless a same-build accuracy/stability evaluation
  justifies promotion.

Lifecycle Audit
================================================================================

Camera:
  Stop clears run flag, joins the processing worker, Flushes/detaches SourceReader,
  releases slots/fences/resources and resets native sequence. Managed Stop clears
  wrappers, presentation, calibration anchors and published sequence. Pause/resume
  preserves a session and is not a provider switch.

MediaPipe:
  Create allocates TaskRunner/graph. DetectAsync transfers packet ownership and
  returns before completion. Runner's publish gate, lifecycle lock, exact submission
  ring, camera-generation checks, and matching in-flight generation reject old or
  unmatched callbacks. Callback-owned result/image data is copied before return.
  Stop closes publication before base Stop/Task Close, waits only lifecycle-critical
  callback sections, disposes tracker/task/pool/resources, and clears submission
  correlation state.

Sentis/backend:
  Submitted jobs snapshot tracker, camera, tracking-session, anchor, and cross-system
  epochs. Stale jobs are retired before ReadbackAndClone when possible. Backend/ROI
  hard reset releases persistent lease and invalidates old jobs.

Provider/Canonical:
  KiwiTrackingProviderHub owns provider arbitration and increments providerGeneration
  only on an actual switch. Resume is not Provider Switch. It normalizes provider
  time/horizontal conventions and will not publish stale frames. Canonical copies
  an immutable coherent latch after Hub refresh; semantic data is accepted only
  when timestamp/backend match rigid and coherence/refiner rules pass.

FacePart:
  Camera/tracking generations constrain transaction slot matching; source/generation/
  size change rebuilds the bounded slot set. Lost/reacquire behavior freezes or
  resumes per channel rather than allowing an old transaction to become a new epoch.

Static conclusion:
  No identified direct path allows a known old camera session, Task callback,
  provider generation, or Sentis job to publish as a current coherent sample.
  This is a Static conclusion, not a Runtime stress PASS.
