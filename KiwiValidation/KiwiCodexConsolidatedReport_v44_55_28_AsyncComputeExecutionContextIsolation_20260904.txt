Public Design Principles
========================
- Unity documents Graphics.ExecuteCommandBufferAsync as dispatching a CommandBuffer on the
  selected async compute queue and guarantees commands inside that buffer execute on the same
  queue:
  https://docs.unity3d.com/cn/6000.0/ScriptReference/Graphics.ExecuteCommandBufferAsync.html
- Unity documents CommandBufferExecutionFlags.AsyncCompute as an execution-intent/validation
  flag for async-compatible commands:
  https://docs.unity3d.com/ja/2022.3/ScriptReference/Rendering.CommandBufferExecutionFlags.html
- Those public contracts support treating queue/execution form as a causal bundle. They do not
  prove which internal dependency or synchronization boundary produced the observed payload.
- A fence is one possible synchronization primitive, not an established fix here. No fence or
  wait should be added until command form, queue transition, and Blit-to-ToTensor dependency
  are isolated.

  contributor candidate.

- Because v20 did not provide a valid canonical observer result and ASYNC did not have a normal
  process exit, the candidate cannot be elevated to authoritative ASYNC_CONTEXT_CAUSAL_CONTRIBUTOR
  under the requested all-gate rule.

Regression Risks
================
- Turning async compute off may restore payload correctness on this machine yet reduce clean
  throughput or increase graphics-queue contention; this run cannot quantify that.
- Adding a fence or blocking wait without isolating the dependency can hide the boundary and
  add latency/deadlock/resource-lifetime risk.
- Treating the GRAPHICS REF closure as a complete Canonical/Avatar PASS would overclaim because
  v20 canonical comparison is invalid and published anomalous coverage is absent.
- Reusing the first launcher behavior can create post-COMPLETE lifecycle ambiguity.
- Observer load changes scheduling and sample availability; timing values must not be promoted
  to clean Production performance evidence.
- A single GPU/driver and one measurement per arm may not establish portability or repeatability.

Production Decision
===================
INVALID_AB.

Do not ship a Production source change and do not remove async compute based only on this v28.
The v27 payload evidence is a strong causal-contributor candidate, but the requested all-gate
acceptance is not met because v20 is INVALID_OBSERVER in both arms and ASYNC lacks a normal
captured process exit. Production remains unchanged. No PASS is claimed for Canonical Semantic,
performance, visual, lifecycle/recovery, or product reliability.
