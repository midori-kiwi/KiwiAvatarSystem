5. First-Principles Target
===============================================================================

Frozen necessary-minimum dataflow:

Newest valid Camera sample
-> Face Landmarker (Primary / Source of Truth)
-> Canonical semantic state
-> Model Profile / stateless mapping
-> atomic Avatar / FacePart binding
-> Presentation
-> Spout

Required invariants:

- Latest valid sample wins; no unbounded or latency-growing FIFO.
- session epoch, frame sequence, timestamp, host ticks, and provider generation remain distinct.
- Invalid, duplicate, out-of-order, stale, mixed-epoch, or broken-transaction publication is
  locally rejected; healthy samples do not acquire arbitrary delay.
- Face texture/crop/mask/landmarks/FacePart state are one sample transaction.
- Face Landmarker is semantic authority; Provider normalization has one owner.
- Head is the one rigid authority. Root translation, Head rotation, Eye/Blink, Mouth/Expression
  remain separate channels.
- Temporal presentation and prediction each have at most one owner per channel.
- Resource ownership and output lifetime are explicit; GPU/CPU transitions are bounded and
  nonblocking on the realtime path unless correctness proves synchronization necessary.
- New filters, smoothing, stale prediction, queue growth, permanent frame delay, Fence/Wait,
  flush, and async disable require boundary-specific evidence.

6. Actual Production + Diagnostic Dataflow
===============================================================================

PRODUCTION, current source:

1) Native Path B captures SystemMemoryNV12 into a bounded latest-frame system and publishes
   sequence/host ticks/generation while maintaining a fixed Unity-visible presentation texture.
2) FaceLandmarkerRunner.Update consumes a fresh source. MediaPipe path keeps one in-flight task;
   Sentis path calls ProcessSentisFreshFrame.
3) KiwiInferenceFaceTracker.TryProcessAsync selects a free lane from a fixed three-lane set.
4) A 192x192 crop/preprocess RenderTexture is filled by Graphics.Blit.
5) Direct mode uses the package's internal TextureConverter CommandBuffer then Worker execution.
   CB Graphics mode appends conversion and scheduling to one external graphics CommandBuffer.
   CB Async mode appends them to an external AsyncCompute CommandBuffer.
6) Worker.PeekOutput returns a borrowed output reference valid only until the next Schedule,
   ScheduleIterable, or Dispose. Current normal lane does not reuse the lane before CPU clone.
7) After submission, AsyncGPUReadback.Request observes output. Completion is polled; then
   ReadbackAndClone copies the logical 1,405 values to observer-owned CPU data and Decode runs.
8) Runner stores result -> provider Hub -> Canonical state -> KiwiFaceMotion and avatar/FacePart.
9) VTuberCamera renders -> VTuberOutput -> KlakSpout persistent output at end of frame.

Static lifetime concern: after-submit early-return/exception paths can leave a pending lane or
borrowed lifetime unresolved. This is not promoted to an observed Runtime failure here.

BUFFER_MAP

QUEUE_MAP

Native latest-wins bounded publication; MediaPipe one-in-flight; Inference free-lane pool=3;
Graphics queue for Direct/CB Graphics; AsyncCompute queue for CB Async; AsyncGPUReadback
completion polling. No justification found for adding another queue or blocking wait.

COPY_MAP / READBACK_MAP

System-memory NV12 -> Unity presentation upload; camera texture -> 192 crop Blit;
TextureConverter -> input tensor GPU work; Worker -> output tensor; output tensor ->
AsyncGPUReadback -> CPU clone -> decode; camera/avatar -> presentation RT -> Spout RT.
The output readback is architecturally required by CPU decode today. Removing it requires a
different decode/consumer boundary and is not justified by this audit.
