- resultPublicationAccepting
- nativeGraphAlive

Exact repaired order:
1. stop new transaction admission through the existing shutdown/reset path;
2. retire result publication independently;
3. retain callback registry, registration, run, and static native delegate;
4. continue lifetime-counting every callback that resolves its registration,
   even after publication retirement;
5. retain the existing CloseAllPacketSources/Cancel behavior;
6. call CalculatorGraph.Dispose while roots are alive;
7. only after Dispose returns mark nativeGraphAlive=false and
   noFutureCallbacks=true;
8. wait only through callback exit accounting, without blocking, until
   activeCallbacks reaches zero;
9. atomically mark roots released and remove the registry entry once;
10. clear the retired run only after root release succeeds.

The callback path now resolves the registry and enters lifetime accounting
under the registry lock before testing result-publication authority. A late
post-retirement callback is counted but returns without publishing. The exit
is in finally and can perform the final nonblocking root release after native
destruction.

Concurrency audit:
- callback begins before retirement: counted; publication depends on the
  independent publication gate; exit is always balanced;
- callback begins after retirement but before graph destruction: counted and
  discarded without publication;
- callback is active when Dispose returns: no-future is marked, root release
  remains gated until that callback exits;
- callback lookup and root release are serialized by CallbackRegistryLock;
- callbackGate is not held while acquiring CallbackRegistryLock during final
  release, so the reviewed paths introduce no lock-order cycle;
- duplicate destruction/root release and counter underflow fail closed.

No sleep, delay, polling loop, spin wait, WaitUntilIdle, WaitUntilDone,
OutputStreamPoller, FIFO Queue, GPU fence/flush, or blocking main-thread wait
was added.
